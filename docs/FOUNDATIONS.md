## Privacy and dependency direction

Private companion prompts, conversations, memories, personality and private goal context must remain outside all Board work records, payloads, metadata and logs. A shared message/ticket runtime whose prompt builder or transcript mirror writes to Board records cannot serve private conversation merely by changing a session label. Orchestration #66 must qualify that separation before companion #8 connects it.

Bootstrap #4 proceeds with explicit unavailable adapters. Account #23 now permits bounded local consumer testing; real binding still needs pilot admission and production account-service qualification. Companion #2 records the native personal route and confirmed shared-host model; actual connections, runtime controls and isolation remain with #7 and the orchestration foundation. Private execution integration waits for orchestration #66. These are upstream contracts, not a circular requirement for downstream companion implementation to already exist. The stopped legacy listener and unresolved pilot cleanup are not reactivated by this work.

The local SQLite store supplies versioned metadata/namespace and internal identity-mapping primitives, not private conversation storage. Its `ready` status is a successful local-open check, not a claim of authenticated per-user persistence. Provisioning is unavailable without an injected validator, and synthetic validation/concurrency tests do not establish real account admission, a qualified pilot or production storage guarantees. The internal HTTP validator is not wired to the server; no cookie parser, sign-in route or provider connection is supplied. Production private-storage access and lifecycle guarantees remain with companion #6.
