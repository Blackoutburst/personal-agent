## Privacy and dependency direction

Private companion prompts, conversations, memories, personality and private goal context must remain outside all Board work records, payloads, metadata and logs. A shared message/ticket runtime whose prompt builder or transcript mirror writes to Board records cannot serve private conversation merely by changing a session label. The companion therefore runs its own per-owner runtime (RUNTIME.md) and never the Board's shared message runtime (orchestration #66 was closed as superseded by this).

Historically, the #5/#6 splits left credential-home placement, native authentication, inference, binding and lifecycle to #7/#8; they did not qualify a runtime through account-only tests. Orchestration #66 was later superseded, as noted above. Current routing is [RUNTIME.md](RUNTIME.md), current application regression coverage is [ISOLATION-TESTS.md](ISOLATION-TESTS.md), and #20/#21 retain their operator release/drill and real-pilot evidence. This history does not authorize restarting an old listener or rerunning its installer.

The shared host administrator is trusted. Separate folders and read-only home mounts do not isolate credential files from another process with the same Unix identity; the accepted current model is application separation under a shared Linux UID. The [private-state contract](PRIVATE-STATE.md) describes its storage/authorization proofs. The foundation-era personal-runtime document is no longer shipped; use [RUNTIME.md](RUNTIME.md). Source tests alone do not establish installed-provider or live deployment behavior.
